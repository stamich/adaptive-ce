# ACE 0.5.1 — release notes (Hardened Release Candidate)

0.5.1 freezes the Planner V5 / TS1 / Format 1.4 behaviour of 0.5.0 **byte for byte** and
qualifies it as the hardened baseline for 0.6: audited decoder arithmetic and resource limits,
frozen binary compatibility fixtures for every earlier format, determinism up to 32 threads,
private-item rustdoc and stricter lints, a fuzz smoke run in CI, repeatable three-run benchmark
qualification with a richer fingerprint, CLI hardening and canonical documentation. It adds
no codec, mode, route or format change.

Previous release: [`history/RELEASE-NOTES-0.5.0.md`](history/RELEASE-NOTES-0.5.0.md).

## Compatibility

| | 0.5.1 vs 0.5.0 |
|---|---|
| Written bytes | identical (golden 0.5.0 with the auto and the scalar SIMD backend, frozen golden 0.4.6) |
| Formats read | 1.0 – 1.4, unchanged; files written by 0.2.1, 0.3.0, 0.4.4, 0.4.6 and 0.5.0 are now frozen test fixtures (`examples/compat/`) |
| Formats written | 1.3, or 1.4 when a block uses TS1 (unchanged) |
| Rust API | additive only; two entry points deprecated (below) |
| CLI | additive (`ace version`); `output == input` is refused; exit status 0 when stdout is closed early |
| MSRV | 1.97.0 (unchanged); builds pinned to Rust 1.98.1 |
| Benchmark documents | schema 2.2 (additive; tools read 2.0 – 2.2) |

### Decoder strictness

0.5.1 rejects a few inputs that 0.5.0 accepted but that no ACE encoder produces (every
compatibility fixture still decodes): a rANS lane whose final state is not the encoder's
initial state, a Huffman stream with more than its zero padding left over, a non-empty
entropy payload for an empty output, an entropy-coded block whose primary stream length
exceeds twice the block size plus 1 KiB, a file declaring more blocks than
`DecodeLimits::max_block_count()` (= `max_index_entries`, now also in the sequential reader),
and an index larger than `max_index_entries` admits. Details: [`COMPATIBILITY.md`](COMPATIBILITY.md).

The primary-stream bound closes a real decompression amplification: a probability-one rANS
model decodes any number of symbols from four bytes, so a 50-byte block could make 0.5.0
produce up to 4 GiB of intermediate output before the codec stage rejected it.

## What changed

### Decoder audit and resource limits
* Parser modules compile with `clippy::arithmetic_side_effects` and
  `clippy::cast_possible_truncation`; every header count is converted with `try_from` (no
  truncation on 32-bit hosts) and checked before any size arithmetic.
* `DecodeLimits` documents which reader applies which limit; `max_block_count()` is enforced
  by every reader; the index allocation is bounded by `max_index_entries`.
* Generated [`DECODER-AUDIT.md`](DECODER-AUDIT.md): field → validation → limit → tests,
  verified by the audit tool. New tests: per-field (0, `u32::MAX`, `u64::MAX`, overflowing
  products), every limit through every reader, and "forged size ⇒ error before allocation"
  measured with a counting allocator.

### Compatibility and determinism
* `examples/compat/`: 48 files written by five earlier releases, never regenerated, decoded
  on every build; inputs are regenerated by frozen integer-only generators.
* Determinism matrix extended to 12 / 16 / 32 workers, in-flight batches 1 / 7 / 64 and
  streaming at 32 workers; tie-break tests (equal NUM1 sizes, candidate order).
* Planner V5 invariants as property tests on every corpus workload and generated input.

### Lints and documentation
* `clippy::unreachable`, `missing_errors_doc`, `missing_safety_doc` denied; `# Errors` on all
  81 public fallible functions; `# Determinism` / `# Invariants` on the planner policies,
  estimators and encoders; rustdoc is built with `--document-private-items` as a gate.
* Canonical, unversioned documents: [`ARCHITECTURE.md`](ARCHITECTURE.md),
  [`FORMAT.md`](FORMAT.md), [`COMPATIBILITY.md`](COMPATIBILITY.md),
  [`SECURITY.md`](SECURITY.md), [`BENCHMARKS.md`](BENCHMARKS.md), [`RELEASE.md`](RELEASE.md),
  [`UNSAFE-AUDIT.md`](UNSAFE-AUDIT.md), [`PANIC-AUDIT.md`](PANIC-AUDIT.md),
  [`API-INVENTORY.md`](API-INVENTORY.md); versioned copies moved to [`history/`](history/).

### API
* Crate docs state which crates are public (`ace-core`, `ace-engine`, `ace-stream`) and which
  are internal; generated [`API-INVENTORY.md`](API-INVENTORY.md) with the planned 0.6 facade.
* Deprecated: `ace_planner::evaluate_candidates_v3` and `evaluate_candidates_v4` (use
  `evaluate_candidates_v4_with_route`); removed in 0.6.
* Added: `DecodeLimits::max_block_count`, `ace_format::INDEX_HEADER_SIZE`.

### CLI
* `ace version`: version, git revision, writer / reader formats, codecs, SIMD and CRC
  backends, toolchain.
* A closed standard output (`ace explain … | head`) ends the command quietly with status 0
  (0.5.0 panicked on `EPIPE`).
* Refuses an output path that names the input file.
* End-to-end tests of the binary (`crates/ace-cli/tests/cli.rs`).

### Fuzzing and CI
* CI job `fuzz-smoke` (15 targets × 25 s) on every push; corpus kept as a CI cache and
  artifact, never committed; release campaign `ACE_FUZZ_SECONDS=600 ACE_FUZZ_CMIN=1`.
* CI failures are re-emitted as check-run annotations.
* Build toolchain pinned to Rust 1.98.1 (1.98.0 has a vtable miscompilation); the MSRV job
  tests 1.97.0 explicitly.

### Benchmarks
* Schema 2.2: git revision and dirty flag, configuration fingerprint, threads, block size, the
  SHA-256 of every generated input.
* `--repeat 3` and `tools/ace-repeatability0.5.1.py`: deterministic values identical across
  runs, macro throughput spread ≤ 5 % (decompression ≤ 15 %), median documents as the release baseline.
* Governor gate: a run on a known non-`performance` governor is `diagnostic`, never `pass`.
* `allocation-profile` family: allocations per block-encoder stage — the 0.5.0 churn on
  `int-sparse-change` BALANCED (~36 bytes per input byte) comes ~94 % from the generic
  evaluator's micro-trials before RunDelta replaces the plan (optimization planned for 0.6).
* `ace-release0.5.1.sh` writes `dist/` with source and benchmark archives,
  `RELEASE-REPORT.md` and `MANIFEST.sha256`.

## Upgrading from 0.5.0

* Nothing to change for files or for `ace-engine` / `ace-stream` users.
* If you lowered `DecodeLimits::max_index_entries`, it now also caps the number of blocks the
  sequential reader accepts.
* Replace calls of the deprecated planner entry points (internal crate) with
  `evaluate_candidates_v4_with_route`.
* Scripts and tools are renamed `…0.5.1`; benchmark result files are
  `benchmark-0.5.1-<family>.json`.

## Release qualification

The automatic pipeline and the manual steps (three benchmark runs and the 15 × 10 min fuzz
campaign on the reference machine, baseline publication in `examples/baselines/0.5.1/`, tag
`v0.5.1`) are described in [`RELEASE.md`](RELEASE.md). Until that run, the latest measured
performance report is [`PERFORMANCE-0.5.0.md`](PERFORMANCE-0.5.0.md): 0.5.1 changes no
encoder, and the decoders only gained validation (an ad-hoc rANS4x decode comparison on the
development VM was within noise).
