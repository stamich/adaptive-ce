# Native interop conventions

Status: ACE 0.7.0. Applies to `crates/ace-ffi`, `include/ace.h` and the JVM bindings in `jvm/`.

ACE is a Rust library. Other languages reach it through one C ABI, `include/ace.h`. This
document fixes the rules every function of that ABI follows, so that a binding written for one
function can be written for all of them. The concrete function list is in [FFI.md](FFI.md).

The conventions deliberately match those of the sibling project AdaptiveDB (`adb.h`), so a
host that embeds both libraries handles errors, handles and strings the same way. ACE has no
dependency on AdaptiveDB, and AdaptiveDB calls ACE as a Rust crate, not through this ABI.

## Language split

| Directory | Language | Content |
|---|---|---|
| `crates/` | Rust | The codec, the engine and `ace-ffi` (the only crate that exports C symbols). |
| `include/` | C | `ace.h`, generated by cbindgen and checked for drift in CI. |
| `jvm/ace-native/` | Java | Panama (`java.lang.foreign`) binding: library loading, ABI check, handles. |
| `jvm/ace-model/`, `jvm/ace-sdk/`, `jvm/ace-stream/`, `jvm/ace-tier/` | Scala 3 | Typed SDK, streams, tier policy. |

Java only holds what must touch `MemorySegment` and `MethodHandle`. Everything with a domain
meaning is Scala and talks to Java through plain values.

## Rules

### 1. Status codes

Every fallible function returns `AceStatus`, an `int32_t`. `ACE_OK` is `0`. Any other value is
an error whose number is part of the ABI and never changes meaning.

| Status | Value | Rust `ErrorKind` |
|---|---|---|
| `ACE_OK` | 0 | none |
| `ACE_ERR_INVALID_ARGUMENT` | 1 | `InvalidConfig` (and null or misaligned arguments) |
| `ACE_ERR_NOT_ACE_FILE` | 2 | `NotAceFile` |
| `ACE_ERR_UNSUPPORTED` | 3 | `Unsupported` |
| `ACE_ERR_CORRUPT` | 4 | `Corrupt` |
| `ACE_ERR_CHECKSUM` | 5 | `ChecksumMismatch` |
| `ACE_ERR_LIMIT_EXCEEDED` | 6 | `LimitExceeded` |
| `ACE_ERR_BLOCK_NOT_FOUND` | 7 | `BlockNotFound` |
| `ACE_ERR_IO` | 8 | `Io` |
| `ACE_ERR_PANIC` | 9 | an internal panic that was caught at the boundary |
| `ACE_ERR_INTERNAL` | 10 | a bug: a state the library believes impossible |

New statuses may be appended. A binding maps an unknown value to a generic error and keeps the
number in the message.

### 2. Last error

On failure the function stores a human-readable message in a thread-local buffer.

- `ace_last_error_ptr()` and `ace_last_error_len()` return the UTF-8 message of the last
  failure **on the calling thread**. The pointer is valid until the next ACE call on that
  thread. It is not NUL-terminated.
- A successful call does not clear the message; read it only after a non-zero status.
- `ace_last_error_block()` returns the block number for `ACE_ERR_CHECKSUM` and
  `ACE_ERR_BLOCK_NOT_FOUND`, otherwise `UINT64_MAX`.

A host that moves work between threads (a JVM virtual thread, a coroutine) reads the message on
the same carrier thread before it yields. Bindings read it immediately after the call.

### 3. Opaque handles

Objects that outlive a call (an engine, a reader, a stream) are opaque pointers: the header
declares `typedef struct AceEngine AceEngine;` and nothing else.

- A creating function takes an out-parameter (`AceEngine **out`) and returns a status. On
  failure `*out` is set to null.
- Every handle type has exactly one release function, `ace_<type>_free`. It accepts null and
  does nothing for it.
- Releasing twice, or using a handle after release, is undefined behaviour. Bindings guard
  against it: Java sets its segment to `MemorySegment.NULL` on close and registers a `Cleaner`
  as a safety net, never as the primary path.
- A handle may be used from one thread at a time. `AceEngine` is additionally safe to share
  between threads, because the Rust `Engine` is `Send + Sync`; this is stated per type in
  [FFI.md](FFI.md).

### 4. Buffers returned by ACE

ACE never returns a raw `malloc`ed pointer to be freed by the caller's `free`. Output bytes are
owned by an `AceBuffer` handle:

- `ace_buffer_data(buf)` and `ace_buffer_len(buf)` expose the bytes. The pointer is valid until
  `ace_buffer_free(buf)`.
- The host copies the bytes out or wraps them (`MemorySegment.reinterpret`) and then frees the
  handle. Wrapping never outlives the handle.

Input is the opposite: the caller owns every input buffer, passed as `(const uint8_t *ptr,
size_t len)`. ACE never keeps a pointer after the call returns. A zero length may come with a
null pointer.

### 5. Strings and structured data

- Text is UTF-8, length-prefixed `(ptr, len)`, not NUL-terminated. NUL-terminated strings are
  used only for the two version strings.
- Structured results (`Stats`, block reports) are returned as JSON in an `AceBuffer`
  (`ace_stats_json`). JSON keeps the C ABI small: adding a field never changes the header.
  The schema is documented in [FFI.md](FFI.md); consumers ignore unknown fields.

### 6. ABI version

`ace_abi_version()` returns a `uint32_t`. It is bumped when a function is removed, a signature
or a status value changes, or a struct layout changes. Adding a function does not bump it.

A binding records the ABI version it was generated against and compares it with
`ace_abi_version()` **before** it looks up any other symbol. A mismatch is a hard error that
names both numbers. `ace_engine_version()` returns the crate version (`"0.7.0"`) for
diagnostics only; nothing branches on it.

ABI v1 ships with 0.7.0. The ABI version is independent of the file format version (1.5).

### 7. Panics and unwinding

No Rust panic crosses the boundary. Every exported function runs its body under
`catch_unwind` and reports a caught panic as `ACE_ERR_PANIC`. The library is built with
`panic = "unwind"` so the catch works; a panic hook is not installed by ACE.

### 8. Memory and limits

- Decoding applies `DecodeLimits` exactly as in Rust. The default limits are the same; the C
  API exposes the six limits through `AceLimits`, which is a plain struct with a leading
  `size_t struct_size` field so it can grow.
- Callers decoding untrusted input set `max_output_size`. A decode that would exceed it fails
  with `ACE_ERR_LIMIT_EXCEEDED` before allocating.
- Sizes are `size_t`/`uint64_t`; counts that Java reads as `long` are never truncated to `int`.

### 9. Threading

Functions that take only plain input and an engine pointer may run concurrently on any number
of threads. The thread-local last error makes this safe without a lock. The library creates no
threads of its own beyond those the engine's `threads` setting requests.

### 10. Determinism

The compressed bytes produced through the C ABI are identical to those of the Rust API for the
same `Config` and input, and identical to ACE 0.6.1 output. The JVM golden-byte tests compare
SHA-256 digests with `examples/golden/0.6.1/`.

## Library loading on the JVM

`jvm/ace-native` locates the library in this order and stops at the first that works:

1. the file named by the system property `ace.native.path`;
2. the file named by the environment variable `ACE_NATIVE_PATH`;
3. the resource `/native/<os>-<arch>/<libname>` inside the JAR, extracted to a temporary file
   that is deleted on exit;
4. `System.mapLibraryName("ace_ffi")` through the normal library path.

`<os>-<arch>` is one of `linux-x86_64`, `linux-aarch64`, `macos-aarch64`, `windows-x86_64`.
After loading, the ABI version is checked (rule 6).

The JVM needs `--enable-native-access=ALL-UNNAMED` (or the module name). The minimum is JDK 22,
where `java.lang.foreign` is final; CI also runs JDK 25.

## What the bindings must not do

- Hand-write signatures for functions that the header declares. Java bindings are generated
  from `ace.h` by `tools/ace-genbindings0.7.0.py`, and CI fails when the committed file differs
  from the generated one.
- Parse or re-implement format logic on the JVM side. The JVM never reads ACE blocks itself.
- Keep a pointer returned by ACE beyond the owning handle.
