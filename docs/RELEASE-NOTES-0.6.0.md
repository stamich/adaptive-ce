# ACE 0.6.0 — release notes (API & Performance)

0.6.0 gives ACE one public Rust API, the `ace` crate, and recovers the decode and allocation
costs the 0.5.1 hardening introduced. It changes **no byte, planner decision, codec, route or
format**: golden 0.5.0 is reproduced exactly with the auto and the scalar SIMD backend, and
the frozen compatibility files of every earlier release still decode. The numeric and float
codecs of the 0.6 plan (RunDelta small deltas, Patched FOR, ALP, Chimp evaluation, Format 1.5)
are **ACE 0.6.1**.

Previous release: [`RELEASE-NOTES-0.5.1.md`](RELEASE-NOTES-0.5.1.md).

## Compatibility

| | 0.6.0 vs 0.5.1 |
|---|---|
| Written bytes | identical (golden 0.5.0, auto and scalar; also through the new API) |
| Formats read | 1.0 – 1.4, unchanged; a newer format is rejected with the ACE release that reads it |
| Formats written | 1.3, or 1.4 when a block uses TS1 (unchanged) |
| Rust API | **replaced**: the `ace` crate; the other crates are internal ([`MIGRATION-0.5-TO-0.6.md`](MIGRATION-0.5-TO-0.6.md)) |
| CLI | commands, options and exit status unchanged; the statistics line of `compress` and `compress-stream` shows the stable counters |
| MSRV | **1.98.1** (was 1.97.0); equals the pinned build toolchain |
| Benchmark documents | schema 2.2 (unchanged) |

## What changed

### The `ace` crate

| Item | Purpose |
|---|---|
| `Engine` | `compress`, `compress_with_stats`, `compress_to`, `compress_stream`, `decompress`, `decompress_into`, `decompress_from`, `open_range_reader`, `explain` |
| `Config`, `ConfigBuilder`, `Profile`, `BlockSizePolicy`, `AccessHint` | settings, validated by `build()` |
| `DecodeLimits`, `DecodeLimitsBuilder` | every limit of the decoder |
| `RangeReader`, `RangeStats` | random access over `Read + Seek` |
| `Stats` | sizes, ratio, format minor, blocks per codec, plan distribution |
| `Error`, `ErrorKind` | failures classified for the caller; `block_id()`; I/O errors keep their source |

The types that may grow are `#[non_exhaustive]`. `docs/API-INVENTORY.md` is generated by the
code audit, which now fails on an undocumented public item and on any `#[deprecated]` item.
Byte equality with the old API, the 0.5.0 golden file, streaming, range reads on all 27
workloads, hostile and truncated input and every decode limit are tested through the facade
(`crates/ace/tests/facade.rs`).

### Internal crates hidden, deprecated items removed

Every crate except `ace` and `ace-cli` is `publish = false` and documented as an internal
building block. `evaluate_candidates_v3` and `evaluate_candidates_v4` are removed.
The `ace` CLI now calls the facade for compress, compress-stream, decompress, verify,
decode-block and read-range; `inspect`, `explain` and `version` show container and planner
details and keep using the internals.

### Forward compatibility

A file of a newer minor format (1.5, written by ACE 0.6.1 or later) is rejected by every
reader with `… (written by ACE 0.6.1 or newer; this reader supports up to 1.4)`, so a user
learns which release to install instead of facing a bare version number.

### Toolchain

MSRV and build toolchain are Rust 1.98.1 (1.98.0 miscompiles some trait-object calls and must
not be used). The separate `msrv` CI job is gone; the `pr` job covers it. Scripts and workflows
are renamed to 0.6.0 (`ace-ci-0.6.0`): update the required status checks in the repository
settings.

### Performance recovery (bytes unchanged)

* **Four-lane rANS decode.** The 0.5.1 hardening replaced the interleave loop of the decoder
  with a per-byte lookup that tests for underflow on every byte. The lane lengths are fixed by
  the expected size, so they are now checked once and the lanes are copied in groups of four.
  No check is weakened. Isolated `rans4x_decode` throughput: 125 → 147 – 157 MB/s (8 MiB, same
  machine). 0.5.1 measured DENSE decode at 0.961× of 0.5.0; the A/B run of the release
  qualification confirms the effect on `compression.dense.decode`.
* **LZ hash tables.** `lz_encode` allocated and cleared a 512 KiB hash table and an 8-byte-per-byte
  chain table for every sample the planner trial-encodes. Each thread now keeps them for inputs
  up to 64 KiB, which covers the samples; longer inputs (the final encode of a block) allocate
  their own, because tracking the touched buckets made that path about 7 % slower (output
  identical, tested against the allocating encoder). Allocation churn per input byte,
  `allocation-profile` family: `int-sparse-change` BALANCED 35.7 → 5.9, `mixed` BALANCED
  16.1 → 8.3, `mixed` DENSE 24.3 → 11.1.

### DENSE versus BALANCED

BALANCED stays the default. DENSE is 0.30 % smaller over the 27 golden workloads (up to 2.6 %
on low-cardinality and floating-point data), costs 34 % more encode time, and is **larger**
on run-dominated data (`zeros` +30 %, `runs` +10.9 %). It is unchanged in 0.6.0 and documented
as not guaranteed to be smaller; making it never worse than BALANCED changes planner decisions
and is planned for 0.6.1. Data and rationale: [`BENCHMARKS.md`](BENCHMARKS.md).

### Benchmarks

New family `public-corpus` (`ACE_PUBLIC_CORPUS=<dir>`, for example Silesia or enwik8): ACE,
LZ4, Zstd-3 and gzip-6 with the lzbench columns. It is skipped when the variable is not set.

## Known limits

* The `ace` crate depends on internal workspace crates, so it cannot be published to crates.io
  as it is: publication needs the internals published too or folded into `ace` — a decision
  for the 1.0 plan. Until then ACE is used as a workspace or git dependency.
* `Config` does not expose `min_gain_bytes`, `enable_early_raw`, `max_in_flight_blocks` and
  `enable_planner_fast_paths`; they keep their defaults.
* `compress_stream` needs a fixed block size and a `Write + Seek` sink.
* Release qualification (three runs on the reference machine, fuzz campaign, baseline
  `examples/baselines/0.6.0/`, `PERFORMANCE-0.6.0.md`, tag `v0.6.0`) follows
  [`RELEASE.md`](RELEASE.md).
