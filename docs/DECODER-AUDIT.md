# ACE decoder audit

> Generated by `tools/ace-code_audit0.5.1.py --write`; do not edit by hand. The audit
> fails when a listed test or fuzz target disappears or a parser module loses its lints.

## Rule

Every integer read from a file reaches an allocation only through
`external integer → try_from → checked_mul / checked_add → DecodeLimits → allocation`.
Sizes that depend on the caller's expected output (block original size) are compared
with it before the output buffer exists. A forged value is an error, never a panic, a
wrap-around or an allocation of the forged size
(`crates/ace-bench/tests/limits_before_allocation.rs` measures the last point).

## Parser modules under the arithmetic lints

| `crates/ace-entropy/src/rans/model.rs` | `:34` Encoder only: `count <= input.len()`, so `count * RANS_SCALE` fits `u64` for any input that fits in memory, `floor <= RANS_SCALE` fits `u16`, and `sum` stays within `256 * RANS_SCALE`. |

| `crates/ace-bitpack/src/scalar.rs` | `:23` `index * bit_width <= values.len() * bit_width`, which `packed_len` proved fits `usize`.<br>`:78` `index * width < count * width`, which `packed_len` proved fits `usize`. |

## Hot decode loops outside the lint

| Module | Why indices cannot escape | Fuzz targets |
|---|---|---|
| `crates/ace-bitpack/src/bitstream.rs` | `BitReader::new` requires `input.len() == ceil(bit_len / 8)`; every read is bounds-checked | `bitstream_roundtrip`, `ts1_decode` |
| `crates/ace-codecs/src/lz.rs` | token lengths use `checked_add` / `get`; output never exceeds `expected_size` | `container_decode`, `engine_roundtrip` |
| `crates/ace-codecs/src/rle.rs` | run / literal lengths use `checked_add` / `get`; output never exceeds `expected_size` | `rle_roundtrip`, `container_decode` |
